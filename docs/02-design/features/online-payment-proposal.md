# 온라인 결제 도입 제안 — 2026-10-15

## 권장: 토스페이먼츠 단일 PG부터

현재 규모와 Supabase + Vercel 구성에는 토스페이먼츠의 주문서형/결제창형 결제를 먼저 검토한다. PG 결제 화면이 결제수단 입력을 담당하고, 사이트 서버는 참가자·주문·금액과 최종 승인 여부를 검증한다. 카드/간편결제부터 시작하고 가상계좌는 입금 웹훅과 미입금 만료 처리를 준비한 뒤 추가한다. 특정 수단의 실제 이용 가능 여부와 수수료는 계약·심사 조건을 확인해야 한다.

여러 PG를 함께 쓰거나 교체할 계획이 구체화되면 PortOne V2 통합을 대안으로 검토한다. 단일 학회의 첫 도입은 연동·정산 경로가 단순한 구성을 우선한다. 이번 변경에는 결제 실행 코드나 PG 키를 추가하지 않았다.

## 구현 흐름

1. 운영자가 회차·참가 구분별 등록비와 취소·환불 기준을 승인한다. 서버가 DB의 금액으로 주문을 생성하며 클라이언트 금액은 신뢰하지 않는다.
2. 로그인한 참가자가 자신의 주문으로 PG 화면에서 인증한다.
3. Vercel 서버가 주문 소유자, 저장한 금액, orderId/paymentKey를 검증한 뒤 PG 승인 API를 호출한다. 성공 URL 방문만으로 납부 완료로 바꾸지 않는다.
4. 승인 결과·거래 식별자·영수증 URL을 `payment_orders`/`payment_events`에 저장한다. PG에서 확인된 결과만 등록비 납부 상태에 반영한다. 이번 수동 확인 내역과 출처를 구분한다.
5. 웹훅 인증/위변조 방지 및 PG API 재조회, 중복 이벤트 멱등 처리, 시간 초과/재시도, 주문과 실제 PG 내역 대사를 구현한다. 가상계좌는 발급과 입금 완료를 별도 상태로 관리한다.
6. 취소·부분취소·전액환불 기록을 보존하고 증빙 상태를 갱신한다. 자동 발급 문서와 PG 매출전표/현금영수증은 문서 종류를 명확히 구분한다.

## 운영자가 확정할 항목

- 실제 수납·정산 주체, 사업자/기관 정보와 정산 계좌, PG 계약 및 심사
- 등록비 구분, 무료/면제 대상, 판매·환불 조건과 문의처
- 회계 증빙 발급 주체와 관련 개인정보 보유기간. 기존 사이트의 학회 종료일까지 보유 방침을 유지했으므로 행사 후 장기 발급 운영 전에 별도 검토·공지 필요
- 테스트 상점에서 성공/실패/중복승인/모바일복귀/환불/웹훅 재전송 검증 후 실결제 전환
