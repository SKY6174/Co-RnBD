# 로그인 이후 저장 흐름 검증 설계

2026-11-07 · [계획](../../01-plan/features/authenticated-lifecycle.plan.md)

## 격리

새 임시 디렉터리에 고유 local project_id와 별도 포트를 사용한다. 현재 config·마이그레이션·메일
템플릿만 복사하며 `.env`·원격 링크·운영 데이터는 복사하지 않는다. 고정 CLI 3.0.0 진입점을 사용한다.
실행 환경의 SUPABASE 관련 변수는 제거하고 명시적 local workdir를 전달한다. 로컬 Auth·REST·Storage·
DB만 사용한다. 테스트 브라우저는 운영 사이트와 *.supabase.co 요청을 차단하며 API·Next 주소가
loopback인지 쓰기 전에 검사한다. 테스트 전용 계정은 @example.test를 사용한다.

새 검증 스크립트가 일회성 환경을 준비하고 Next production build를 로컬로 실행한다.
로컬 관리자 키는 fixture 생성에만 사용하고 출력·증거·Git에 저장하지 않는다.
모든 업무 저장은 사용자 로그인 JWT와 실제 UI/API로 실행한다. 검증 결과·스크린샷·합성 PDF는
지정한 외부 출력 폴더에 저장한다. 종료 시 이번 프로젝트의 컨테이너만 중지한다.

## 시나리오

1. 프로필 저장·유지, 투고 초안·공동저자·PDF·제출, 비배정 회원/익명 접근 차단.
2. 위원장 UI로 심사위원 두 명 배정, 심사 임시저장·제출과 비위원장 판정 차단.
3. 위원장 수정 요청, 저자 재투고, 재심사 두 명, 채택·최종본 제출·다운로드·확인.
4. 참가 신청 UI 저장·수정·중복 방지, 위원장 확정·체크인과 상태 재조회.
5. 발급기관·등록비/납부 UI 저장, 발급 전 조건 거부, 세 문서 발급·실제 저장·A4 PDF.
6. 다른 회원·익명 열람/발급 거부, snapshot 위조 차단, 동시 발급 중복 방지,
   환불/체크인 취소/참가 취소 후 문서 취소와 재발급, 로그아웃 후 개인 화면 제거.

현재 DB 제약·RLS·최신 chair RPC를 기준으로 검증하며 과거 고정 날짜·fixture에 의존하지 않는다.

## 빈 DB 재생 오류 수정

`20260925190050`의 플랫폼 함수 권한 회수는 함수가 있을 때만 수행한다. 함수가 있는 경우 기존
권한 회수는 그대로 실행한다. `20260927151538`의 운영 관리자 선행 계정 검사는 Auth가 완전히 빈
신규 설치에서만 건너뛴다. 이미 계정이 있는 설치에는 기존의 두 인증 계정 요구를 유지하며,
빈 설치에 임의의 관리자 권한을 부여하지 않는다. 이미 적용된 운영 마이그레이션은 재실행하지 않는다.
새 DB 전체 재생과 populated DB의 거부 조건을 모두 검증한다.

## 로그인 직후 입력 보존

프로필 조회 전에 작업 공간이 표시되어 사용자가 입력한 이름·소속을 늦은 응답이 덮어쓰는 문제가
실제 로그인 검사에서 재현되었다. 최초 작업 공간은 프로필·권한·원고·심사 조회를 마친 뒤 표시한다.
로그아웃·세대 변경 후 늦은 응답이 작업 공간을 다시 표시하지 못하게 기존 generation 확인을 유지한다.
프로필 요청 처리 중 작업 공간이 숨겨져 있는지 직접 검사하고 바로 입력·저장·재조회로 확인한다.

실패가 나오면 테스트 조건과 제품 결함을 구분하고, 제품 수정 전 해당 설계·정책을 확인한다.
타입·빌드·관련 회귀·diff 검사 후 PR을 머지한다. 운영 배포 뒤에는 쓰기 없는 전체 페이지 검사를 사용한다.
