# 세션 좌장 운영 — 설계

## 데이터와 권한

- `session_chairs`: `session_id`당 1명의 로그인 계정, 보고 메모와 제출 시각. 세션의 공개용 `moderator` 문자열과 로그인 권한은 별개다.
- `session_presentations`: 채택된 원고와 구두·포스터 세션의 연결, 실제 발표자 이름, 제목 스냅샷, 발표 여부, 추천 여부, 진행 메모. 원고 PDF와 심사 내용은 이 테이블에 복제하지 않는다.
- 위원장만 좌장과 발표 목록을 배정·교체·해제한다. 좌장은 자기 세션의 발표 여부·추천·진행 메모만 수정하고, 모든 발표의 출석을 기록한 뒤 보고서를 제출한다. 보고서 제출 후 수정은 위원장이 재개할 때까지 막는다.
- 좌장 계정은 `staff_roles`의 `chair`로 승격되지 않는다. 세션 배정 여부를 Postgres RLS와 변경 방지 트리거에서 확인한다. 새 테이블은 RLS를 켜고 필요한 권한만 준다.
- 배정 세션과 원고는 동일 회차여야 하고 원고가 `accepted`이며 `final_presentation`이 세션 형태와 일치해야 한다. 발표자 이름은 위원장이 확인한 값으로 입력한다. 현재 회차에서만 기록을 수정할 수 있다.

## 화면

- `operations.html`: 위원장이 각 구두·포스터 세션에서 좌장 계정 이메일로 권한을 부여하고 채택 원고·발표자를 배정한다. 보고서 제출 및 추천 현황을 확인한다.
- `session-chair.html`: 기존 로그인 세션을 사용한다. 자기 세션만 표시하고 출석·추천·메모를 저장한 뒤 보고서를 제출한다. 우수발표 추천은 확정 수상이나 논문 심사가 아님을 명시한다. 미추천 가능.
- 투고 화면에서 좌장 업무 링크와 역할 구분을 제공한다. 공개 안내에는 좌장의 역할만 설명하고 신청 자격·마감·시상 규정은 확정 전으로 남긴다.

## 검증 및 배포

마이그레이션은 재현 가능한 파일로 작성한다. 로컬 DB에서 역할별 허용/거부 경로와 제출 후 잠금을 확인하고, Next.js 타입 검사·빌드 및 데스크톱·모바일 화면을 확인한다. 운영 DB에는 PR 검토와 배포 승인 전 적용하지 않는다.
