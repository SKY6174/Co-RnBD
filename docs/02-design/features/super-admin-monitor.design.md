# 공동위원장 현황 모니터링 — 설계

## 권한

`staff_roles`에 기본값 `false`인 `is_super_admin` 열을 추가한다. 두 계정은 기존 `chair` 역할을 유지하므로 배포 전 운영 화면도 동작한다. 두 이메일은 확인된 `auth.users` ID와 대조해 일회성 마이그레이션에서 표식을 부여한다. 이메일 변경이나 신규 가입으로 자동 승격하지 않는다. 브라우저는 본인 역할과 표식을 확인하고 모니터링 메뉴를 표시한다. DB의 기존 RLS가 개인정보 접근 권한을 강제하고, 모니터링 화면은 슈퍼 관리자만 보여 준다.

## 화면과 데이터

`monitor.html`은 현재 `conference_editions` 회차의 `attendee_registrations`와 `papers`를 직접 읽는다. 참가자는 프로필의 이름·소속·이메일을 매칭한다. 신청 상태(대기·확정·취소), 체크인, 참가일을 표시한다. 논문은 제목·분야·상태·연락 담당자·제출일을 표시한다. 모든 사용자 입력은 HTML 이스케이프한다.

모든 행을 배치로 읽어 집계와 검색 결과가 API 기본 페이지 크기에 잘리지 않게 한다. 상태·참가 구분·참가일·모집 분야 필터, 로딩·빈 결과·오류 상태와 다시 불러오기 버튼을 제공한다. 이 화면에서 개인정보 다운로드나 상태 변경은 제공하지 않는다. 기존 위원장 운영/투고 화면으로 이동하여 조치한다.

## 배포 순서

마이그레이션은 열 추가와 두 계정 표식 부여를 한 트랜잭션으로 적용한다. 되돌릴 때는 두 계정의 표식을 `false`로 복원하고 열을 제거한다. 사이트 코드는 `is_super_admin`을 인식한 뒤 배포한다. 기존 위원장 기능은 마이그레이션과 사이트 배포 사이에도 계속 작동한다.
