# 운영 지정 계정 심사 생명주기 검증 — Design

field-editor-review, smart-review-workspace, review-email/paper-submitted/author-receipt 설계를 기준으로 한다.
실행 대상은 co-rnbd.org와 기존 Supabase production 한 곳으로 고정한다. 운영 쓰기는 이번 사용자 요청으로
허용된 합성 원고 1건·2회 제출·4회 배정/심사·수정/채택 판정으로 제한한다.

## 계정·인증·자료

심사위원장 계정은 저자와 위원장 화면을 각각 열고, 두 기존 테스트위원은 심사와 AE 화면을 분리한다.
기존 현재 회차의 담당 명부와 인증/프로필 조건을 먼저 검사한다. 관리자 키는 연결된 CLI에서 메모리로만
받아 지정·기존 인증 계정의 일회성 magic link 생성에만 사용하고 브라우저에는 주지 않는다. 비밀번호/역할을
바꾸지 않는다. 브라우저는 정상 Auth verify 경로로 인증한다. 세션·토큰·키는 출력·커밋하지 않으며 임시 상태
파일은 0600/상위 0700으로 제한한다. URL/에러에 포함된 인증 토큰도 진단 출력에서 가린다.

PDF는 검증용 1페이지 두 버전이며 연구·기업 정보가 없다. 원고 제목에 [E2E TEST]와 실행 식별자를 넣고
단독 저자만 등록해 심사위원 본인/공동저자 이해관계를 피한다. 회원 프로필은 덮어쓰지 않는다.

## 실행·검증

작성·업로드·제출·배정·심사·판정은 실제 배포 화면을 사용한다. DB는 해당 원고의 결과/이력/메일 확인만 한다.
다음 단계로 진행하기 전에 그 단계 메일이 발송 서비스에 접수됐는지 확인해 오래된 배정 취소와 혼동하지 않는다.
필요하면 기존 queue worker를 호출하되 대기 메일이 해당 테스트 원고/지정 수신자뿐일 때만 호출하고 간격을 둔다.
일반 workflow의 is_test=false를 유지해 실제 수신자/역할/제출본 검증을 우회하지 않는다.

신규/재제출 각 3건(저자 접수 확인·담당 AE·위원장), 배정 각 2건, 2인 의견 각 4건, AE 판정 각 1건을
예상한다. 두 회차 합계는 20건이며 AE/심사위원 겸임의 동일 이벤트 중복은 발생하지 않아야 한다.
Provider의 Delivered를 event provider ID/종류/시각과 대조하며 단순 sent와 구별한다.

다른 분야 AE의 편집 목록·판정 차단, 현재 제출본의 2인 심사 요건, 이전 PDF/의견 보존, 저자 익명화,
재제출 후 새 심사·판정 및 최신 화면을 확인한다. 데스크톱/모바일 증거는 비공개 임시 디렉터리에 저장한다.
발견한 문제는 별도 작은 수정과 격리 회귀로 검증하며 운영 테스트 원고는 삭제하지 않는다.
롤백은 직전 배포 복원이고 이미 발송된 메일은 보존한다. 설정과 다른 운영 자료는 변경하지 않는다.

## 운영에서 발견한 겸임 계정 목록 문제

첫 배정 뒤 다른 분야 AE가 심사위원으로 배정된 원고를 편집 목록에서도 보았다. 기존 papers RLS는 저자·배정
심사위원·AE 조회 권한의 합집합이므로 편집 화면은 목적에 맞는 범위를 별도로 좁혀야 한다. DB 판정 검사는 유지한다.

chair.js는 활성 AE 명부의 담당 분야만 조회·선택하게 하고, 원고 소유자·공동저자·이해관계 거절 이력 원고는
AE 목록/통계/상세에서 제외한다. 위원장 전체 목록과 개인 심사 배정 접근은 보존한다. owner_id·저자 이메일은
기존 RLS로 허용된 원고의 편집 목록 필터에만 사용한다. 새 DB 권한/엔드포인트/메일 규칙은 추가하지 않는다.
격리 검증에 타 분야 겸임 배정, 본인 소유, 공동저자 목록 제외와 실제 reviewer 화면 접근·DB 판정 거절을 추가한다.
