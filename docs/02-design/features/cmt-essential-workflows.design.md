# CMT 필수 운영 흐름 보강 — Design

> 2026-09-26 · [계획](../../01-plan/features/cmt-essential-workflows.plan.md) · 기존 `paper-submission-system`에 추가

## 기준

CMT의 역할·단계는 참고하되 우리 행사는 저자, 심사위원, 위원장 3개 화면을 유지한다. 심사위원 두 명의 간단한 권고를 위원장이 종합한다. 별도 메타심사·자료집 편집자·자동 배정·입찰·외부 재위임은 만들지 않는다. 판정은 저장 즉시 저자의 로그인 화면에서 보이며 자동 이메일은 보내지 않는다.

## 데이터 모델

`conference_settings` 단일 행에 `submission_deadline`, `reviews_open`, `review_deadline`, `final_uploads_open`, `final_deadline`을 추가한다. 기한은 nullable `timestamptz`이며 한국시간 입력 UI에서 UTC ISO 값으로 전송한다. 단계가 꺼져 있거나 설정된 기한이 지났으면 DB가 관련 쓰기를 거부한다. 기존 접수 개폐 `submissions_open`은 유지한다.

`paper_files`에 `file_stage` (`submission` 또는 `final`)를 추가하고 기존 행은 `submission`으로 취급한다. 채택 전에는 `final`을 삽입할 수 없으며, 채택 원고의 소유자만 최종본 단계가 열려 있을 때 올릴 수 있다. 저장소는 기존 비공개 `paper-pdfs` 버킷과 UUID 경로를 사용한다. 버전 번호는 두 단계 전체에서 증가한다.

원고 작성자는 접수 단계가 열려 있어야 새 초안과 첫 제출을 할 수 있다. 위원장 수정 요청(`revision`)의 재제출은 일반 접수 종료 후에도 허용한다. 심사위원은 `under_review` 배정에서 심사 단계가 열려 있을 때만 임시저장·제출할 수 있고, 이해관계 거절은 단계 종료 후에도 가능하다. 위원장은 언제나 상태를 확인하고 판정할 수 있다.

## RLS와 검증

- `papers_insert`와 `guard_paper_update`가 접수 개폐·기한을 확인한다.
- 제출 상태로 바꿀 때 저자 1명 이상을 DB에서 확인하고, 공동저자 이메일의 형식·길이를 제한한다. 브라우저 검증을 우회한 빈 저자 명단도 접수하지 않는다.
- `guard_review_update`가 심사 개폐·기한을 확인한다.
- `reviews` 삽입 트리거는 배정 대상 계정의 이메일이 `paper_authors.email`과 같으면 거부한다. 소속/과제 이해관계는 이메일만으로 판별할 수 없으므로 위원장이 저자 명단을 보고 확인한다.
- `paper_files`와 `storage.objects` 삽입 정책은 채택 원고의 최종본에만 새 경로를 허용한다.
- `paper_files`와 `storage.objects` 조회 정책은 최종본을 소유자와 위원장에게만 허용한다. 기존 심사용 PDF는 배정 심사위원에게 계속 허용한다.
- 신규 공개 테이블은 만들지 않는다. 기존 RLS 범위, 프로필/역할 권한을 유지한다.

## 화면 흐름

`submission.html` 상단에는 접수·심사·최종본 단계 상태와 한국시간 마감을 표시한다. 위원장 화면에는 단계별 토글과 선택적 마감 시각 폼을 둔다. 빈 마감은 시간 제한 없음이며, 마감 후에는 체크박스가 켜져 있어도 실제 단계는 종료된다. 접수된 원고 수/상태별 건수와 원고 저자 정보를 위원장에게 표시해 배정·판정을 돕는다.

저자는 기존 초안/제출/수정/결과 화면을 유지한다. 채택 원고를 열면 별도 최종 PDF 입력이 보인다. 단계가 닫혔으면 업로드 버튼을 잠그고 이유를 표시한다. 파일 목록에 `투고본`과 `최종본`을 구분한다. 심사위원은 기존 이해관계 확인·임시저장·권고 화면을 쓰되, 단계 종료 시 편집 불가 안내를 본다.

하단의 역할별 도움말은 CMT 메뉴를 이 행사에 맞춰 계정, 저자, 심사위원, 위원장, 채택 후 최종본으로 정리한다. 추가 계정 연결, 계정 병합, 학회 사이트 개설, 메타심사 등은 이 행사에 적용되지 않는다고 안내한다.

## 구현 파일

- `supabase/migrations/<CLI 생성 이름>.sql`: 컬럼, 트리거, RLS 정책
- `site/submission.html`: 단계 상태, 위원장 폼, 최종본 폼, 도움말
- `site/submission.js`: 단계 로드/저장, 최종본 업로드, 요약과 안내
- `site/submission.css`: 모바일 반응형 단계/도움말 스타일

## 검증

1. 마이그레이션을 연결된 프로젝트에 적용하고 컬럼·정책·트리거를 재조회한다.
2. 트랜잭션 롤백 범위에서 접수 마감, 심사 마감, 공동저자 배정 거절, 최종본 권한을 검사한다. 시험용 사용자/원고를 본운영 DB에 남기지 않는다.
3. `node --check`, 정적 HTML/JS 참조 검사, 390px 및 데스크톱 화면 검토를 수행한다.
4. Supabase 보안 advisory와 Git/Vercel 배포 상태를 확인한다.
