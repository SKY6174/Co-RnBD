# 스마트 투고·심사 작업 공간 — Design

기존 field-editor-review와 author-receipt-notifications 설계를 따른다. 변경 대상은 submission/chair HTML,
legacy JS, 두 CSS와 격리 브라우저 검증이다. DB migration/API/수신 설정을 추가하지 않는다.

## 저자·심사위원

기존 히어로에 투고→2인 심사→AE 판정 안내를 보완하고 로그인 작업 공간에 실제 데이터 요약을 추가한다.
프로필 미완성, 수정 요청, 진행 가능한 심사를 우선 안내한다. 원고·수정 요청·남은 심사 요약은 해당 탭/필터로
이동하며 검색 조건을 초기화한다. 심사 미개방/판정 공개 뒤에는 제출을 권하지 않는다. 전문분야 미입력도 안내한다.

내 원고는 제목/접수번호 검색과 상태 필터, 심사 배정은 제목/접수번호 검색과 내 심사 상태 필터를 제공한다.
원고 카드에 작성/접수/심사/판정의 현재 단계, 실제 상태별 다음 행동을 텍스트로 표시한다. 수정 요청은
판정 뒤 수정본 대기임을 명시하고 진행률을 임의 백분율로 표현하지 않는다. 심사 카드는 원고 상태 외에
본인 심사 상태를 별도로 표시한다. 기존 저장/제출/거절/다운로드 경로를 그대로 사용한다.

기존 탭에 id/aria-controls/aria-labelledby, roving tabindex, 좌우/Home/End 키 동작을 보완한다.
검색 결과 수만 짧은 polite 영역으로 지연 안내한다. 필터 사용은 열려 있는 작성 양식의 입력을 지우지 않는다.

## 편집 업무

기존 역할 범위로 받은 목록에서 배정/진행/판정/최종본 확인 수를 계산한다. 필터 통계는 선택한 분야에 맞춘다.
가장 먼저 처리할 단계와 해당 필터 버튼을 안내하며 AE에게 배정·최종본 확인을 직접 수행하도록 권하지 않는다.
목록에는 현재 제출본 유효 심사 2건의 제출 수를 native progress와 숫자로 함께 표시한다.
상세에는 상태 기반 다음 단계와 원고/PDF·심사·판정·알림 내부 링크를 제공한다. 완료되지 않은 심사는
완료로 표시하지 않고 기존 판정 제약/예외 확인 dialog를 유지한다. 목록 복귀 시 원래 관리 버튼으로 초점을 돌린다.
이메일 기록은 최신 3건을 보여 주고 나머지는 native details로 펼친다. 발송 서비스 접수와 Delivered를 혼동하지 않는다.

## 시각·검증

forest/teal/ivory 배경, 라임 강조, 명확한 위계, 넉넉한 여백, 상태별 텍스트/색상, 반응형 그리드를 사용한다.
새 컨트롤은 native button/input/select, 명시적 label, 44px 목표 크기, focus-visible, 감소된 모션을 지원한다.
modern-web-guidance accessibility의 실제 탭 동작/명시적 라벨/포커스 원칙을 적용한다.

7개 기존 실제 로그인/투고/재심/두 분야 AE/권한 검증과 v1~v4 8개 메일 경계를 유지하고,
새 요약·필터·결과 없음/초기화·키보드·1440/390px overflow·읽기/빈 상태를 추가 검증한다.
TS/build/node syntax/diff 및 Preview/운영 공개 화면을 확인한다. Preview는 운영 DB에 쓰지 않는다.
