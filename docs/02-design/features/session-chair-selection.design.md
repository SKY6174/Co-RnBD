# 세션 좌장 모집·선정 — 설계 제안

이 문서는 구현 전 검토안이다. 아래의 정책 결정이 끝나기 전에는 공개 모집을 열지 않는다.

## 권장 흐름

1. 위원장이 확정된 모집 요건·기간·결과 안내 방식을 입력하고 모집을 연다. 기본 상태는 닫힘이다.
2. 기존 계정으로 로그인한 지원자가 이름·소속·전문 분야를 `profiles`에서 확인한다. 구두·포스터 희망 형태와 행사일 중 현장 참여 가능한 날짜를 선택해 지원한다. 별도 전화번호·주소는 받지 않는다.
3. 위원장은 지원자의 전문 분야, 현장 가능 날짜와 현재 프로그램 수요를 검토한다. 선정 사유·추가 이해관계 확인 결과는 내부 메모로 남긴다. 자동 점수나 자동 선정은 사용하지 않는다.
4. 선정 상태는 지원자 본인에게만 보인다. **선정은 계정 권한 부여가 아니다.** 위원장이 실제 세션을 지정해 `session_chairs`에 배정할 때만 세션별 열람·보고 권한을 준다. 공개 프로그램의 좌장 이름은 별도 공개 승인 후 표시한다.
5. 지원자는 배정 전 지원을 철회할 수 있다. 배정 후에는 해제 요청을 위원장에게 보내고, 위원장이 기존 보고서 잠금·발표 운영 영향을 확인해 재배정한다.

## 데이터와 경계

- `conference_settings`에 현재 회차의 `chair_applications_open`(기본 `false`)과 선택한 마감 시각을 둔다. 모집을 열 때 승인된 안내 문구와 마감 시각이 있어야 한다. 과거 회차 지원·수정은 닫는다.
- 새 `session_chair_applications`에 `(edition_year, user_id)` 유일값, 희망 발표 형태, 참여 가능한 행사 날짜, 상태(`submitted`, `approved`, `declined`, `withdrawn`), 접수·검토 시각, 배정 후 해제 요청 시각을 둔다. 이름·이메일·소속·전문 분야를 중복 저장하지 않고 `profiles`에서 읽는다. 위원장 내부 메모는 별도 `session_chair_application_reviews`에 두고 위원장만 읽는다. RLS만으로는 같은 테이블의 메모 열을 지원자에게 숨길 수 없기 때문이다.
- 지원자는 자기 지원서만 읽고, 모집 중 미선정 상태의 희망 형태·날짜를 바꾸거나 배정 전 철회할 수 있다. 철회 후 모집 기간에 다시 지원하면 같은 행을 `submitted`로 되돌린다. 배정 후에는 해제 요청 시각만 기록할 수 있다. 위원장만 전체 지원서와 내부 메모를 읽고 선정 상태를 변경한다. 새 테이블의 RLS, 현재 회차 확인, 허용 상태 전이, 입력 길이·날짜 검증은 DB에서 강제한다.
- `approved`만으로 `staff_roles` 또는 `session_chairs` 접근 권한을 주지 않는다. 실제 배정 시 승인된 같은 회차 지원자인지 DB에서 확인한다. 기존 직접 배정 기록이 있을 경우 마이그레이션 전 현황을 확인해 보존하며, 일괄 승인 기록을 꾸며 넣지 않는다.
- 프로필의 전문 분야(`applied`, `industry`, `convergence`, `education`)는 지원 전 1개 이상 입력하도록 안내한다. 학력·직급 또는 특정 기관 소속을 자동 자격 판정에 쓰지 않는다. 저자 본인·이메일 일치 공동저자 충돌 차단은 기존 트리거가 담당하고, 같은 기관·과제 관계는 위원장이 확인한다.
- 지원 취소가 배정과 충돌하면 자동으로 좌장 보고서나 발표 기록을 삭제하지 않는다. 위원장에게 해제 요청 상태를 표시하고 재배정·보고서 재개 순서를 안내한다. 개인정보 보존·삭제 범위는 기존 개인정보처리방침과 함께 검토한다.

## 화면과 알림

- 공개 모집 안내: 자격, 현장 참여, 일정, 선정 기준, 결과 확인 방법이 확정될 때만 CFP와 프로그램에 신청 링크를 표시한다. 확정 전에는 기존의 ‘선정 방식 추후 안내’ 문구를 유지한다.
- 지원 화면: 기존 Supabase 로그인 사용. 마감·닫힘·이미 지원·철회·선정·배정 상태와 오류를 명확히 보여 준다. 제출 확인에는 ‘지원 접수’라고 표시하고 선정·권한 부여로 오인시키지 않는다.
- 위원장 화면: 지원자 목록, 전문 분야·가능 날짜, 내부 검토 메모, 선정·미선정, 배정 전 철회 상태를 관리한다. 세션을 선택할 때 승인된 지원자만 선택 가능하게 하고, DB에서 다시 검증한다.
- 자동 이메일·공개 후보 명단은 만들지 않는다. 선정 결과는 로그인한 지원자 화면에 표시한다. 이메일 안내가 필요해지면 수신자와 템플릿·발송 환경을 별도로 승인한다.

## 운영 주체가 확정할 항목

| 결정 | 권장안 | 확정 전 처리 |
| --- | --- | --- |
| 모집 방식 | 기존 계정 사용자의 자발적 지원, 위원장 검토 | 지원 화면 비공개 |
| 지원 자격·선정 기준 | 분야 적합성, 현장 가능 여부, 이해관계·기관 편중을 종합 검토 | 자격 제한·자동 탈락 없음 |
| 참가 등록 조건 | 지원과 참가 신청은 분리하고, 최종 세션 배정 전 등록 필요 여부를 결정 | 등록 상태로 지원을 차단하지 않음 |
| 모집 마감·결과 안내일 | 확정된 날짜와 채널만 게시 | 날짜·선정 결과 예고를 게시하지 않음 |

## 구현·검증 순서

정책 확정 후 작은 마이그레이션과 지원·위원장 화면을 구현한다. 로컬 DB에서 본인/타인/위원장 읽기·쓰기, 미선정자의 배정 거부, 철회와 기존 배정의 충돌, 회차 전환을 확인한다. 브라우저에서 데스크톱·390px 화면과 닫힘·빈 목록·제출·오류 상태를 확인한다. Preview가 운영 Supabase를 사용하면 실계정·실지원서 쓰기 테스트는 피한다. 운영 DB 적용과 공개 모집 시작은 별도 단계로 나누고, 모집은 확정된 요건을 입력할 때까지 닫아 둔다.
