## 반영 내용
- 공개 화면에 저자 투고, 심사위원 배정·심사, 위원장 판정 절차를 안내하고 CFP의 분량·가안 일정으로 연결했다.

## 2026-10-15 실제 로컬 통합 검증

운영과 동일한 23개 마이그레이션 및 app_private 함수 25개 정의 해시를 대조한 독립 로컬 Supabase에서 실제 Auth/Postgres/Storage/브라우저로 검수했다. 운영에는 읽기만 수행했으며 원고/심사/파일 0건과 단계 설정 유지, 새 RPC 미적용을 마지막에 확인했다.

발견: 운영 관리 HTML의 paper-settings-form 누락으로 초기화 중단; revision 저장의 트리거/RLS 거부와 병렬 저자 삭제로 저자 유실. 복구 양식, 중복 양식 대신 설정 링크, revision 유지 편집 허용, SECURITY INVOKER 저자 교체 트랜잭션 RPC를 준비해 로컬에만 적용했다.

수정 후 15개 단계 점검 통과: 실제 계정/프로필 → 초안·저자·PDF → 제출 → 배정 → 닫힌 심사 차단 → PDF 다운로드·심사 임시저장/제출 → 위원장 수정 요청·저자 결과 표시 → 수정본 v2 재제출 → 위원장 채택·세션 배정 → 닫힌 최종본 차단 → 최종본 v3 → 위원장 파일 해시 일치. 비배정 열람 및 심사위원 최종본 열람 차단도 포함한다. 추가 6개 검사에서 잘못된 저자 교체의 원자성/행 ID 보존, 비소유자/익명 RPC 거부, draft→revision 임의 전이 거부, PDF 필수 및 접수 종료 후 revision 재제출을 확인했다. 타입/빌드/JS 문법/diff 통과.

자동 판정 이메일, 전체 판정 변경 이력/판정자, 최종본 검수완료 상태는 현재 구현에 없다. 이번 테스트에서 배정 거절/반려/재심사 라운드/OAuth/실메일/동시 부하는 검증하지 않았다. UI/권한 관련 오류 수정은 검토용이며 운영 적용 완료를 의미하지 않는다. 상세 증거는 로컬 outputs/submission-lifecycle-20261015/report.md와 JSON/스크린샷에 남겼다.

## 2026-10-15 운영 DB 반영

사용자의 후속 진행 요청으로 `20261014220144_fix_revision_save_and_atomic_authors`를 운영 Supabase에 적용했다. 저장소 파일명도 실제 적용 이력에 맞췄다. 수정한 트리거와 RPC의 정의 해시는 로컬 통합 검증 대상과 동일하며, 수정본 RLS 허용 조건·SECURITY INVOKER·빈 search_path·익명 실행 금지·인증 사용자 실행 권한을 확인했다. 운영 원고는 0건이고 접수 열림/심사 닫힘/최종본 닫힘 설정은 유지했다.

프런트는 PR #47의 Vercel Preview 빌드가 통과했다. 이 기록 시점에는 운영 프런트 병합·배포 전이며, 배포 후 실제 도메인 읽기 검수 결과는 PR과 로컬 검수 보고서에 기록한다. 실제 운영 사용자로 투고·판정·메일을 실행한 것은 아니다.


## 2026-10-15 위원장 전용 원고 심사 관리

`chair.html`에서 접수 목록·검색·상태/분야 필터, 심사위원 검색·전문 분야·진행 건수, 배정/교체, 심사 의견, 판정 공개, 최종본 확인, 처리 이력을 제공한다. 운영/현황의 링크와 기존 `submission.html#chair` 진입도 전용 화면으로 연결하고 로그인 후 복귀한다. 기존 저자·심사위원 기능과 발표 편성/분야 집계를 유지한다.

DB: 현재 제출 시각별 심사 배정을 보존하며 교체한 배정의 권한을 회수한다. SECURITY INVOKER RPC가 배정과 상태 변경을 원자적으로 처리한다. 판정은 최신 원고 시각 대조·공개 메모·미완료 심사의 예외 사유를 검사하고 판정자/공개 시각을 기록한다. 이력은 내부 트리거만 쓰며 위원장만 읽는다. 최종본 확인은 실제 최신 PDF ID에 연결되어 새 업로드 시 재확인이 필요하다.

실제 로컬 Auth/Postgres/Storage/브라우저 통합 검증 9개 묶음 통과: 로그인 복귀·운영 링크, PDF 제출/이력, 비위원장·익명 RPC/가짜 이력 차단, 중복·자기 원고·실패 교체 롤백·기존 배정 접근 회수, 예외 사유와 판정 공개, 수정본 재심사/과거 의견 보존/오래된 판정 거부, 최종본 v3 확인 후 v4 재확인, 이력 변경·저자 열람 차단, 검색·390px·구형 링크 이동·JS 오류 없음. 타입/빌드/문법/diff 검사도 수행했다. 검수 중 원고 열기에 필요한 공통 분야 상수 누락을 수정하고 전체 흐름을 다시 검증했다.

자동 결과 이메일은 포함하지 않으며, 예외 판정 사유는 저자에게도 공개된다. 신규 이력 기능 이전의 과거 활동을 소급 생성하지 않는다. OAuth 제공자/실메일/부하 시험은 이번 검수 범위가 아니다. 운영에는 시험 계정·원고를 만들지 않는다. 상세 증거는 `outputs/chair-desk-verification/`에 저장하며 운영 DB/배포 최종 상태는 PR과 로컬 보고서에 기록한다.

운영 DB에 `20261014222650_chair_review_desk`를 적용했다. 새 테이블의 RLS, 인증/익명 권한과 공개 RPC의 SECURITY INVOKER를 확인했고, 변경 함수 6개의 정의 해시가 로컬 검증 대상과 일치했다. 운영 원고/심사/파일은 0건이며 단계 설정을 유지했다. 보안 점검에는 기존 회차 생성·활성화 함수의 SECURITY DEFINER 경고 2건만 남으며 신규 경고는 없다. 참고: https://supabase.com/docs/guides/database/database-linter?lint=0029_authenticated_security_definer_function_executable
