# 원고별 심사위원 2명 정책

## 적용 규칙

- 현재 제출본마다 서로 다른 유효 심사위원 2명 필수. 거절·철회·이전 제출본 배정은 제외한다.
- 0/1명은 **배정 필요**, 2명 중 미완료는 **심사 중**, 2명 모두 의견을 제출하면 **판정 대기**.
- 배정 수와 제출 수를 각각 2명 기준으로 표시. 정원 충족 후에는 교체할 기존 배정 선택을 요구한다.
- 2명 미만의 채택·수정 요청·반려는 UI와 DB에서 차단하며, 공개 예외 사유를 넣어도 우회할 수 없다.
- 2명 배정 후 심사 미완료 상태의 위원장 예외 판정은 기존처럼 5자 이상 사유를 요구하고 저자에게 공개한다.

## DB 반영

`20261014232610_require_two_reviewers.sql`을 운영 프로젝트에 적용했다. 기존 `guard_chair_decision` 트리거 함수를 교체하며 RPC와 직접 UPDATE 모두에 동일한 조건을 적용한다. 심사 행 잠금과 최신 스냅샷 대조는 유지한다. 기존 최대 2명 배정 검사·유일 제약·RLS·파일 접근 정책은 유지한다.

적용 직전/직후 운영 원고와 심사 0건 확인. 기존 기록 수정 없음. 적용한 함수 정의의 MD5는 로컬 검증 DB와 운영 모두 `56d893a7f0e78a1e19c151fd09a4e730`이다. 내부 함수의 anon/authenticated 직접 실행 권한은 없으며 papers/reviews RLS는 활성 상태다.

## 검증 결과

실제 로컬 Auth/Postgres/Storage와 브라우저로 다음을 확인했다.

- `verify-chair-desk.py`: 10개 그룹 통과. 0/1명 판정 거부(공개 예외 사유 포함), 직접 UPDATE 우회 거부, 1명 심사 완료의 판정 대기 제외, 2명 배정 시 추가 배정 차단 및 3번째 API 배정 거부, 중복·공동저자 거부, 교체 원자성/권한 회수.
- 2명 중 미완료일 때 사유 없는 판정 거부, 공개 예외 사유를 통한 수정 요청, 수정본에 새로운 2명 배정, 2명 모두 심사 제출 후 정상 채택, 최종본 v3/v4 확인 및 이력 검증 통과.
- `verify-chair-concurrency.py`: 6개 그룹 통과. 심사/판정 동시 처리, 오래된 스냅샷/구버전 클라이언트 거부, 최신 심사 재확인, 모바일 판정, 이해충돌 거절로 1명이 되면 판정 차단, 대체 위원 배정 확인.
- 1440px/390px 화면, JS 오류 없음, JS 문법·TypeScript·프로덕션 빌드·diff 검사 통과.
- 검증 중 native option의 disabled 여부는 Playwright의 일반 요소 is_disabled 대신 실제 DOM 속성 및 select의 native checkValidity로 확인하도록 보완했다.

운영에서 실사용자 명의 투고나 이메일 발송은 하지 않았다. 인증된 쓰기 검증은 별도 로컬 DB에서 수행했다. 배포 후 운영 스크립트 해시·2명 안내·익명 권한 차단과 모바일을 `verify-portal-production.py`로 확인한다.
