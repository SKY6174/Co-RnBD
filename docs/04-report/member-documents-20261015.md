# 마이페이지 증빙 자동 발급 — 검증 보고서

## 반영 범위

사용자가 운영자 PDF 업로드 대신 **등록정보로 자동 발급**을 선택했다. 마이페이지, 위원장 증빙 관리, A4 증빙 보기·인쇄/PDF 저장 화면을 추가했다. 홈페이지·등록·투고·운영 메뉴와 연결했고 이메일/소셜 로그인 복귀는 고정 경로만 허용한다.

| 문서 | 발급 조건 |
|---|---|
| 참가확인증 | 발급기관 설정 + 참가 확정 + 현장 체크인 |
| 영수증 | 발급기관 설정 + 참가 확정 + 등록비 양수 + 실제 납부 수동 확인 |
| 거래명세서 | 발급기관 설정 + 참가 확정 + 등록비 내역 설정 |

문서 내용은 DB에서 당시 회원·학회·발급기관·납부 정보를 읽어 고정한다. 새 번호로 발급하고 기존 내용을 수정하지 않는다. 같은 문서의 중복 발급 요청은 기존 번호를 반환한다. 납부 정보 변경·환불, 참가 취소 및 체크인 철회는 관련 증빙을 취소한다. 이미 인쇄·저장한 사본은 회수할 수 없다.

## 설계 대비 검증

`verify-member-documents.py`가 실제 격리 로컬 Auth/Postgres와 Chromium으로 8개 그룹을 통과했다.

1. 발급기관 미설정/참가 미확정/체크인 전 차단, 일반회원의 기관·납부 정보 쓰기 차단.
2. 자동 발급, 미납 영수증 차단, 위조한 금액·이름·발급번호·처리자로 문서를 생성할 수 없음, 발급 스냅샷 변경 차단.
3. 다른 회원의 문서/납부 조회와 발급·취소 차단, 익명 접근 차단.
4. 세 종류 A4 PDF 각각 1페이지, 390px 마이페이지·관리·증빙 화면 가로 넘침 없음. PDF 렌더 이미지를 직접 확인.
5. 동시 4건 발급이 동일 문서 반환, 환불 후 영수증 출력/재발급 차단, 음수 금액 거부.
6. 비공개 아카이브 회차의 본인 참가 내역/기존 문서 접근 유지.
7. 체크인 후 기존 취소 제한 유지, 체크인 철회·본인 참가 취소 시 문서 취소, 로그아웃 시 개인정보 DOM 삭제, 로그인 후 마이페이지 복귀.
8. 홈페이지 메뉴 390/1024/1440px 가로 넘침 없음. 브라우저 예외 없음.

아카이브 검증 후 로컬 테스트 회차만 복원했다. 아카이브 불변성 트리거는 복원 거래 내에서 재활성화 여부까지 확인했으며 RLS/Auth는 계속 활성 상태였다. 운영에서는 참가 기록·납부 기록 생성, 실사용자 로그인, 이메일 발송을 하지 않는다.

## 운영 설정과 한계

- 발급기관과 등록비는 임의 입력하지 않았다. 위원장이 `/document-admin.html`에서 확인된 기관·대표자·주소·문의처를 설정하고 자동 발급을 켜야 한다.
- 온라인 결제/입금 자동 대사/실제 환불은 구현하지 않았다. 납부 상태는 운영자가 외부 내역을 확인해 기록한다. 영수증은 주최기관 납부 확인용이며 세금계산서·현금영수증 자동 발행 기능은 없다.
- PDF는 증빙 화면의 **인쇄 / PDF 저장**으로 저장한다. 서버가 PDF 파일을 보관하거나 직인 이미지를 자동 삽입하지 않는다.
- 기존 개인정보 보유기간(2027-01-22)을 임의로 연장하지 않았다. 행사 후 장기 발급 운영 전 보유기간을 별도로 검토·공지해야 한다. 회차별 UI와 DB 관계가 장기 보유 자체를 승인하는 것은 아니다.
- [온라인 결제 도입 제안](../02-design/features/online-payment-proposal.md)에 토스페이먼츠 단일 PG 권장안과 PortOne 대안, 서버 승인·웹훅·환불·멱등 처리 요구사항을 정리했다.

## 배포·롤백

`20261015071750_registration_documents.sql`을 운영 Supabase에 적용해 세 테이블, RLS, 내부 검증 트리거, 발급·취소 RPC를 추가했다. 로컬/운영 발급 검증 함수 해시 `9154456df6f684b9c951d039fc6d1231` 일치, 세 테이블 RLS 활성, anon RPC 및 내부 함수 직접 실행 불가를 확인했다. 적용 직전/직후 운영 참가 기록과 새 기관·납부·문서 기록은 0건이다. 보안 advisor는 기존 회차 관리 함수의 경고 2건만 있으며 새 경고는 없다. JS 문법·TypeScript·Next 19개 페이지 빌드·diff 검사를 통과했다. 기존 참가·투고 데이터 및 Storage 정책은 바꾸지 않는다. 기본 발급기관 행은 없고 자동 발급도 꺼진 상태다. 문제 시 신규 발급 설정을 닫고 이전 Vercel 배포로 복원한다. 발급/취소 기록은 삭제하지 않는다. 배포 후 readonly `verify-member-documents-production.py`로 소스 일치·익명 차단·화면을 확인한다.
