# 투고·위원회 기본 정보 입력 계획

## 목표

작은 전문대학 학술대회에 맞춰 계정, 원고, 심사 활동에 필요한 최소 정보를 수집한다. 기존 Google·Naver·이메일 로그인과 역할별 권한은 유지한다.

## 범위

- 공통 프로필: 필수 이름·기관, 선택 학과/부서·직위·ORCID. 로그인 이메일은 읽기 전용이다.
- 원고: 연락 담당자 이름·이메일은 제출 시 필수다. 키워드는 선택 항목이며 입력 시 2~5개로 한다. 초안은 미완성 정보를 허용한다.
- 위원회: 배정된 심사위원과 위원장에게 기존 모집 분야 중 전문 분야 1~3개와 위원 명단 공개 선택권을 제공한다. 원고별 이해관계 확인은 현행 심사 절차를 사용한다.
- 필수 프로필은 제출 또는 첫 심사에 앞서 완성하게 하며, 기존 원고의 조회와 초안 편집은 막지 않는다.
- DB 제약, 브라우저 유효성 검사, RLS를 함께 적용하고 운영 DB와 웹 배포를 검증한다.

## 제외

전화번호·주소·생년월일·사진 수집, 공개 위원 명단 페이지, 자동 심사위원 매칭, 공동저자 계정 확인, 학술지급 복잡한 이해관계 도메인 관리.

## 성공 기준

1. 새 필드를 모바일과 데스크톱에서 입력·수정·재조회할 수 있다.
2. 미완성 공통 프로필·원고 연락처는 제출을 통과하지 못한다. 키워드는 생략하거나 2~5개 입력할 수 있다.
3. 심사위원은 전문 분야를 1~3개 선택해야 심사를 제출할 수 있다.
4. 기존 계정과 원고를 삭제하거나 노출하지 않으며, 익명 사용자는 새 정보를 조회·수정할 수 없다.
5. 마이그레이션을 운영 DB에 적용하고 웹을 배포한 뒤 Git 원격에 push한다.

## 위험 및 대응

- 기존 자료 호환성: 새 칼럼에 안전한 기본값을 두고 최종 제출 시점만 강화한다.
- 별도 작업의 선행 마이그레이션: 원격 이력과 로컬 파일을 일치시킨 뒤 새 마이그레이션을 적용한다.
- 개인정보 노출: 프로필의 기존 자기·위원장 조회 RLS를 그대로 사용하며 공개 명단 동의만 저장한다.
